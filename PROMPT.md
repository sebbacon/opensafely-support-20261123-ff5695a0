Investigate the reported problem and propose a focused fix that follows the repository’s existing conventions.

Clearly distinguish what you observed, what you measured, and what you infer. State uncertainties alongside the relevant claim. Label synthetic data before giving any patient counts, and never imply those counts describe the real cohort.

Where practical, run tests and benchmarks. Report what actually ran, what the checks cover, and what remains unverified. Synthetic improvements do not establish that a production problem is resolved.

Keep changes within scope. Explain every additional change, including small optimisations, in plain language. Present incidental housekeeping separately.

Make the proposal easy to apply: identify required code changes, regression tests, optional benchmarking scripts, and documentation. Include this guidance in the change summary itself, and link to the proposed code.

Lead with a short, accessible answer: what likely caused the problem, what changed, what evidence supports it, and what the user should check next. Put technical detail after that.
